# Guest iOS App (v1, door-only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native SwiftUI iPhone app a guest installs once, scans an invite QR to enroll, and then taps to open the Gate or the Out-door.

**Architecture:** Single-screen app. On launch it reads a saved session (API base + device token) from the Keychain; with none, it shows a QR scanner. Scanning an invite QR yields the Funnel base URL and a one-time code; the app enrolls (`POST /guest/enroll`), stores the returned token in the Keychain, and shows the home screen with two action buttons. Each button `POST`s to the guest API with a `Bearer` token. A 401 (revoked) wipes the session and returns to the scanner. No camera/video in v1 (deferred to the streaming plan).

**Tech Stack:** Swift 6 / SwiftUI, iOS 17 deployment target. Zero third-party dependencies — Keychain via `Security`, QR via `AVFoundation`, HTTP via `URLSession` async/await. Project is defined in a text `project.yml` and generated with XcodeGen.

**Spec:** docs/superpowers/specs/2026-10-21-guest-mobile-app-design.md

## Global Constraints

- Native Swift/SwiftUI only. No cross-platform framework, no third-party package dependencies.
- iOS deployment target: **17.0**. Build/test on simulator `iPhone 17`.
- App lives in the camonitor repo at **`apps/ios/`** (builder's-call: monorepo keeps app + backend contract together; changing it is a path move).
- Bundle id **`net.khaledez.homeaccess`**, display name **"Home Access"**, scheme **`HomeAccess`** (cosmetic; one line in `project.yml` to change).
- The device **token is stored only in the Keychain** — never `UserDefaults`, a plist, or any log line.
- The **API base URL is never hardcoded.** It is derived at enrollment from the scanned QR and persisted with the token.
- **QR payload contract (shared with the QR generator):** the QR encodes the enroll endpoint with the code as a query parameter — `https://<host>/guest/enroll?code=<enrollCode>`. The app derives `apiBase` by trimming the trailing `/guest/enroll` from the URL's path; subsequent calls are `apiBase + "/guest/gate/open"` and `apiBase + "/guest/outdoor/open"`.
- Guest API semantics (from the backend, frozen): `POST /guest/enroll` body `{"code":"…"}` → `200 {"token":"…"}` | `400` (invalid/expired code) | `500`. `POST /guest/gate/open` and `POST /guest/outdoor/open` with header `Authorization: Bearer <token>` → `204` success | `401` (bad/revoked token) | `502` (device didn't respond). Timeouts/offline surface as a network error.
- v1 scope is **Gate + Out-door only.** No camera tiles, no streaming, no owner/admin screen (admin QR is generated on the tailnet web UI — separate plan).

## Review Focus

- **Revoked mid-use:** an action returns `401` → app clears the stored session and returns to the scanner, does not silently retry or keep showing the home screen. (Task 5)
- **Bad/used/expired code:** enroll returns `400` → scanner shows a clear "invite expired or already used" message and keeps scanning, no crash. (Task 5)
- **Foreign/garbage QR:** a scanned string that isn't our `…/guest/enroll?code=…` shape is rejected by the parser (returns nil), the scanner keeps running, no enroll attempt is made. (Task 3)
- **Action failure vs success:** `502` and network/timeout errors never render as "opened"; the button re-enables and shows a distinct "couldn't reach the gate" message. (Task 3 client mapping, Task 5 UI)
- **Offline at launch:** a saved session loads and the home screen renders without any network call; failures only occur on a button tap. (Task 2 + Task 5)

    SessionStore.clear()

    try SessionStore.save(s)
    XCTAssertEqual(SessionStore.load(), s)

    SessionStore.clear()

func testOverwrite() throws {
    try SessionStore.save(Session(apiBase: URL(string: "https://h")!, token: "one"))
    try SessionStore.save(Session(apiBase: URL(string: "https://h")!, token: "two"))
    XCTAssertEqual(SessionStore.load()?.token, "two")

- [ ] **Step 2: Run tests, verify they fail** (`SessionStore` undefined).

- [ ] **Step 3: Implement `SessionStore`**

JSON-encode `Session`; `save` does `SecItemDelete` then `SecItemAdd` (idempotent overwrite); `load` does `SecItemCopyMatching` and decodes, returning nil on any miss; `clear` does `SecItemDelete`. Keychain works on the simulator, so tests run in CI.

**Interfaces:**
- Produces:
  - `struct Invite: Equatable { let apiBase: URL; let code: String }`
  - `func parseInviteQR(_ raw: String) -> Invite?` — accepts only an `https` URL whose path ends in `/guest/enroll` with a non-empty `code` query item; `apiBase` is that URL with the path and query stripped (scheme+host+port). Returns nil otherwise.
